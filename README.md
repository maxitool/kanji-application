# KanjiApplication 🖌️

**KanjiApplication** — это клиент-серверное мобильное приложение под Android для интерактивного **обучения каллиграфии и распознавания японских иероглифов (кандзи)** на основе систем искусственного интеллекта. Проект изначально разрабатывался в рамках выпускной квалификационной работы бакалавра на кафедре Теоретической и прикладной информатики НГТУ.

Приложение помогает пользователям изучать правильное начертание кандзи, проверять корректность написания черт в реальном времени, осуществлять рукописный поиск иероглифов и организовывать их по собственным группам для эффективного повторения.

## 🚀 Основной функционал

*   **Рукописный поиск кандзи:** Рисование иероглифа на холсте внутри приложения и отправка его на сервер для распознавания нейросетью.
*   **Режим интерактивного тестирования:** Написание кандзи в контексте целого слова (с подсказками по фуригане и переводу) с последующей оценкой каллиграфии алгоритмом.
*   **Анимация последовательности черт:** Визуализация правильного порядка и направления написания линий (*Sequential Draw*).
*   **Собственные группы обучения:** Создание персональных списков иероглифов и добавление туда новых кандзи прямо из карточки информации.
*   **Предустановленные уровни:** Встроенные блоки обучения, сформированные на базе популярного учебника *Kanji Look And Learn* и охватывающие 512 иероглифов.

## 🛠️ Архитектура и технологии

Проект построен по клиент-серверной архитектуре и сочетает в себе несколько языков программирования для достижения максимальной производительности:

### 📱 Клиент (Android-приложение)
*   **Языки:** Java (основная логика) + C++ (нативная оптимизация алгоритмов нормализации).
*   **Сборка:** Gradle (поддержка модулей, CMake / Android NDK).
*   **Технологии:** Android Jetpack (`Fragments`, `Navigation UI`), архитектура многопоточности для обработки холста рисования.
*   **Сторонние библиотеки:** `pl.droidsonroids.gif:android-gif-drawable` (для высокопроизводительного рендеринга анимаций порядка начертания иероглифов).
*   **Связь с С++:** Использование **JNI (Java Native Interface)** для вызова высокопроизводительных нативных алгоритмов фильтрации и нормализации изображений.

### 🧠 ИИ и Сервер (Распознавание)
*   **Языки:** Python + C++.
*   **Нейросеть:** Многоуровневая система **свёрточных нейронных сетей (CNN)**, состоящая из главного классификатора (определение иероглифа в одну из 54 групп по визуальным признакам) и 53 вторичных классификаторов для точного распознавания конкретного кандзи.
*   **Связь на сервере:** Использование библиотеки `ctypes` для интеграции скриптов на Python и высокопроизводительного кода на C++.

## 📐 Алгоритм нормализации изображений (C++)

Перед отправкой на нейросеть нарисованный пользователем иероглиф проходит строгую математическую предобработку, написанную на языке C++ для оптимизации ресурсов:

1.  **Выделение главной части:** С холста рисования считывается только ограничивающий прямоугольник (Bounding Box), содержащий линии, а пустые пространства по краях отбрасываются.
2.  **Удаление пустых пространств:** Если размер внутренних пустых промежутков по вертикали или горизонтали превышает 15% от размера всего изображения, эти промежутки принудительно сжимаются до 15% (для компенсации размашистого почерка).
3.  **Динамическое сжатие (Downsampling):** Изображение масштабируется до целевого размера 64x64 пикселя по формуле:
    $$NS_{ij} = \frac{\sum_{w \cdot h} HS_{ij} \cdot ostW \cdot ostH}{compW \cdot compH}$$
    где $compW$ и $compH$ — степени сжатия по осям, а $ostW \cdot ostH$ — дробные части граничных пикселей. Для маленьких изображений (менее 64px) применяется аналогичная ресурсоемкая процедура "Расширение $\rightarrow$ Сжатие".
4.  **Исправление выбросов (Binarization):** Очистка полутонов и шумов — пиксели со значением яркости менее 0.3 полностью зануляются (белый фон), а пиксели ярче 0.98 приравниваются к 1.0 (чистый черный цвет линии).

## 📊 Модель данных ИИ и База данных

### Структура нейросетей (CNN)
Все классификаторы построены на базе следующей архитектуры сверточных слоев:
*   `Conv2D(32, (3,3))` + `Dropout(0.2)` + `Conv2D(32, (3,3))` + `MaxPooling2D((2,2))`
*   `Conv2D(64, (3,3))` + `Dropout(0.2)` + `Conv2D(64, (3,3))` + `MaxPooling2D((2,2))`
*   Полносвязные слои: `Dense(512)` + `Dropout(0.2)` + `Dense(256)` + `Dense(классы, Softmax)`
*   **Оптимизаторы:** Nadam / Rmsprop, функция потерь — Cross-entropy.
*   **Датасет:** 55 296 изображений (512 иероглифов $\times$ 12 начертаний $\times$ 3 наклона $\times$ 3 разрешения). Входной слой принимает матрицу 64x64x1.

### Протокол сериализации данных (Socket)
Передача данных между Android-клиентом и сервером происходит в закодированном текстовом формате без пробелов для минимизации трафика:
*   Каждый пиксель вещественной матрицы трансформируется в строгое 3-значное число (1-й знак — целая часть, следующие 2 знака — дробная часть).
*   Пример: пиксели со значениями `(0.98, 0.00)` сериализуются в строку `"098000000100..."`.

### Схема Базы Данных (SQLite)

Внутри Android-приложения (в папке `assets/`) находятся две локальные реляционные базы данных, обеспечивающие структурированное хранение лингвистических параметров:

1.  **kanji_information.db** — основное хранилище информации об иероглифах, примерах использования и системных тренировочных блоках:
    *   **Таблица `INFO`** — карточки иероглифов:
        *   `ID` (INTEGER, Primary Key) — уникальный числовой идентификатор, используемый также для динамической привязки графических ресурсов начертания (`i` + ID).
        *   `KANJI` (TEXT, Unique) — сам символ японского иероглифа (кандзи).
        *   `READING` (TEXT) — чтения иероглифа (онъёми/кунъёми).
        *   `MEANING` (TEXT) — перевод и значения.
    *   **Таблица `MAIN_GROUPS`** — предустановленные учебные группы по уровням сложности:
        *   `ID` (INTEGER, Primary Key) — идентификатор блока.
        *   `LEVEL` (TEXT) — уровень сложности («Уровень 1», «Уровень 2», «Уровень 3»).
        *   `NAME` (TEXT) — имя/номер группы.
        *   `LIST_KANJI` (TEXT) — сплошная символьная строка иероглифов, входящих в данный блок.
    *   **Таблица `TASKS`** — база предложений и слов для контекстных тестов:
        *   `WORD` (TEXT) — целевое слово, содержащее изучаемый кандзи.
        *   `FURIGANA` (TEXT) — чтение слова, записанное азбукой хирагана с пробельными разделителями.
        *   `ROMAJI` (TEXT) — англоязычная транслитерация.
        *   `TRANSLATION` (TEXT) — перевод слова на русский/английский языки.
        *   `GROUP_KANJI` (TEXT) — текстовый маркер связи и итерации тестов.

2.  **kanji_groups.db** — пользовательская база данных для управления персональными коллекциями иероглифов:
    *   **Таблица `GROUPS`** — кастомные списки кандзи, создаваемые пользователем:
        *   `ID` (INTEGER, Primary Key) — инкрементный идентификатор пользовательской группы.
        *   `NAME` (TEXT, Unique) — уникальное название папки/коллекции, задаваемое пользователем.
        *   `LIST_KANJI` (TEXT) — динамически обновляемая строка из символов кандзи, добавленных пользователем в данную группу.

## 💻 Обзор ключевых экранов (Activities)

1.  **MainActivity:** Главный экран с панелью для рисования кандзи и кнопкой быстрого рукописного поиска.
2.  **InformationActivity:** Отображает подробную информацию об иероглифе: чтения (онъёми/кунъёми), значения, а также примеры слов и интеграцию с карточками обучения.
3.  **TaskActivity:** Модуль тестирования, который динамически подбирает случайные задания из выбранной группы, скрывает кандзи в слове и просит пользователя воспроизвести его на холсте.
4.  **ResultTaskActivity:** Экран подведения итогов тестирования с выводом процента правильных ответов, точной статистики и визуальной оценкой в виде звезд.
5.  **TaskCardActivity:** Карточка детального изучения иероглифа, запускающая пошаговую анимацию написания каждой черты в строго правильном каллиграфическом порядке.
6.  **OwnGroupsActivity & AboutBlockActivity:** Экраны управления пользовательскими коллекциями кандзи, позволяющие структурировать учебный процесс под индивидуальные задачи.

## 🔧 Запуск и развертывание

### Системные спецификации окружения клиента
*   **Compile SDK:** 32 | **Target SDK:** 32 | **Min SDK:** 28
*   **Java Compatibility:** 1.8 (Java 8)
*   **CMake Version:** 3.22.1 (встроен в нативный билд-процесс через Android NDK)

### Сборка клиента
1. Запустите сервер с ИИ (инструкция по запуску находится здесь ).
2. Склонируйте репозиторий:
   ```bash
   git clone https://github.com
   ```
3. Откройте проект в Android Studio.
4. Дождитесь автоматической синхронизации Gradle и сборки С++ файлов через CMake.
5. Запустите проект на эмуляторе или физическом устройстве (не ниже Android 9.0, API 28).
   *(Важно: при работе на официальном эмуляторе Android Studio приложение автоматически транслирует запросы к Socket-серверу хоста по специальному зарезервированному адресу `10.0.2.2`, чтобы связать сетевые потоки смартфона с вашей локальной машиной).*
